Mobs míticos para tu servidor, sin complicaciones.

NMythic trae jefes, boosts con súbditos, 16 mecánicas de habilidades, spawners, recompensas, rangos y un editor web con IA — todo en archivos YAML que se validan antes de recargar.

Paper/Spigot 1.20 – 1.21 16 mecánicas · 6 disparadores 12 idiomas Editor web + IA Backups 48h
Instalar en 2 minutos Ver ejemplos de mobs

Novedades de la 1.1.0 NUEVO

  • Puertos de hosting estilo Plan para el editor web: variable de entorno (web.port-from-env), bind-address 0.0.0.0, fallback automático de puerto y dirección pública configurable. Ver sección →
  • Comando /nm wiki con enlaces clicables a la wiki de NMythic y la de NShop; también en el editor GUI y en el editor web (/api/wiki).
  • MiniMessage mezclado con códigos legacy: ahora puedes combinar &a con <gradient> en el mismo texto sin romper nada.
  • Validador de sintaxis más listo: los códigos HEX <#ff2020> dentro de comillas ya no se confunden con comentarios.

Instalación y requisitos

NMythic no tiene dependencias obligatorias. Funciona en Paper y Spigot 1.20.x y 1.21.x.

1 · Descarga NMythic.jar→ 2 · Copia a /plugins→ 3 · Reinicia el servidor→ 4 · /nm help
RequisitoDetalle
ServidorPaper / Spigot / Purpur — 1.20 a 1.21 (API 1.20)
Java17 o superior (bytecode 17)
OpcionalesItemsAdder, Nexo u Oraxen para items con texturas (IA:, NEXO:, ORAXEN:)
DatosSQLite automático (data.db) con fallback a YAML — no requiere MySQL
Primer arranque: NMythic crea la estructura de carpetas y copia 5 mobs, 3 boosts, 2 archivos de habilidades, 2 spawners, rewards.yml y ranks.yml de ejemplo para que copies y pegues.

Arranque y banner

En cada arranque verás un resumen con lo cargado y el tiempo:

[NMythic] ✔ 5 mobs, 3 boosts, 4 habilidades, 2 spawners (141ms)
[NMythic]  Datos: sqlite | Idioma: en_US | Web: http://127.0.0.1:8765

Fundamentos de mobs/*.yml

Cada archivo de mobs/ es un mob mítico. El nombre del archivo es su ID (mobs/duende.yml → /nm spawn duende).

# mobs/duende.yml — el archivo de ejemplo incluido
config-version: 2          # no toques esto: lo usa el migrador
type: ZOMBIE               # entidad base de vanilla (ZOMBIE, SKELETON, IRON_GOLEM, VEX, BAT...)
display-name: "&aDuende del Bosque &7[lv.]"   #  se sustituye
level: 3                   # nivel (solo visual, para tu lore)
health: 24                 # vida
damage: 6                  # dano de ataque
speed: 0.28                # velocidad (0.23 ~ zombie normal)
follow-range: 40           # radio de deteccion
xp: 8                      # xp extra al morir (ademas de la vanilla)

equipment:                 # equipo opcional (cada pieza es un item)
  main-hand: { material: WOODEN_SWORD, name: "&aGarra duende" }
  helmet:    { material: LEATHER_HELMET, unbreakable: true }

drops:                     # drops personalizados (se suman a los vanilla)
  - { material: EMERALD, amount: 1, chance: 0.4, name: "&aEsmeralda duende" }
  - { material: ROTTEN_FLESH, amount: 2, chance: 0.8 }

skills: [duende_grito, duende_veneno]   # ids de skills/*.yml

options:
  custom-name-visible: true
  glowing: false
  silent: false
  timer-interval: 30       # cada cuantos segundos salta onTimer (0 = nunca)
Importante: usa 2 espacios para indentar, nunca TAB. El validador te avisará con línea y columna exactas.

Equipo y drops

Los slots de equipment son helmet, chestplate, leggings, boots, main-hand y off-hand. Cada item admite:

CampoEjemploNotas

name / lorename: "&bArco glacial"colores legacy/hex/MiniMessage
amount1 – 64solo tiene sentido en drops
chance0.4 (40%)solo drops; si falta, 100%
enchants{ SHARPNESS: 3 }encantamientos

custom-model-data1001para resource packs

Opciones y nombre

En display-name puedes usar <level> (nivel del mob) y <hp> (vida máxima). Los mobs míticos:

  • no desaparecen solos al alejarse (persistent),
  • se limpian con /nm killall [mob],
  • pueden marcarse como súbditos cuando un boost los invoca (ver súbditos).

Fundamentos de boosts/*.yml

Un boost es un evento temporal: los mobs afectados aparecen más fuertes, con efectos extra (sub-boosts) y escoltados por súbditos. Se activa con /nm boost start <id> [segundos].

# boosts/luna_sangrienta.yml — el ejemplo incluido
config-version: 2
display-name: "<gradient:#ff2020:#7a0000>&lLuna Sangrienta</gradient>"
applies-to: all            # all o lista: [duende, espectro]
duration: 300              # 5 minutos por defecto

multiplier:                # se aplica a los mobs que aparezcan DURANTE el boost
  health: 1.5
  damage: 1.25

announce:                  # anuncio multicanal al iniciar / terminar
  start:
    bossbar: { text: "<gradient:#ff2020:#7a0000>&lLuna Sangrienta</gradient> &7— los mobs se enfurecen", seconds: 8, color: RED }
    chat: "&c&l☠ La Luna Sangrienta se alza…"
    sound: { name: ENTITY_WITHER_SPAWN, volume: 1, pitch: 0.6 }
  end:
    chat: "&7La &cLuna Sangrienta &7se ha retirado."

sub-boosts:                # se sortean al aparecer cada mob (ver abajo)
  - { chance: 0.25, effect: SPEED, seconds: 120, amplifier: 1 }
  - { chance: 0.15, effect: STRENGTH, seconds: 120, amplifier: 0 }

minions:                   # subditos (ver abajo)
  mob: murcielago_sangriento
  amount: 4
  radius: 40
  per-mob: false
  despawn-on-end: true

Sub-boosts

Cada vez que aparece un mob afectado por el boost, se sortea cada sub-boost por separado:

ClaveQué hace
chanceprobabilidad (0–1) de aplicar esta regla
effect / seconds / amplifierefecto de poción permanente al aparecer (acepta nombres 1.20 y 1.21)
extra-damage+dano fijo
extra-health+vida fija

Súbditos (minions)

La sección minions invoca escoltas. Con per-mob: false aparecen dispersos en un radio amplio alrededor de un jugador aleatorio (o del spawn si no hay jugadores): perfecto para eventos globales. Con per-mob: true aparecen alrededor de cada mob que nazca durante el boost.

Global (luna_sangrienta)

4 murciélagos dispersos en radio 40 alrededor de un jugador. Al terminar el boost, los súbditos restantes se eliminan (despawn-on-end: true).

Escolta (furia_duendes)

2 súbditos en radio 6 junto a cada duende que nazca. El boost termina a los 180s o con /nm boost stop furia_duendes.

En juego: /nm boost start luna_sangrienta 600 · /nm boost list (muestra tiempo restante) · /nm boost stop <id> · y desde el editor GUI con un clic en el ícono del boost.

skills/*.yml

Una habilidad agrupa mecánicas bajo disparadores. Los mobs las referencian por id en skills: [id1, id2].

# skills/duende_skills.yml
duende_grito:
  onSpawn:
    - { mechanic: sound, name: ENTITY_ZOMBIE_AMBIENT, volume: 1.2, pitch: 1.4 }
    - { mechanic: particle, name: VILLAGER_ANGRY, count: 12 }
  onTimer:
    - { mechanic: heal, percent: 8 }      # regenera 8% de su vida

duende_veneno:
  onAttack:
    - { mechanic: potion, effect: POISON, seconds: 4, chance: 0.3 }
  onDamaged:
    - { mechanic: velocity, mode: push, strength: 0.8, chance: 0.25 }

Todas las mecánicas aceptan chance (probabilidad) y target: self|target cuando aplica.

Los 6 disparadores

DisparadorCuándo saltaContexto
onSpawnal aparecer el mob—
onDeathal morirtarget = asesino
onAttackel mob golpea (incluye sus proyectiles)target = víctima
onDamagedun jugador golpea al mobtarget = atacante
onTargetel mob elige objetivotarget = objetivo
onTimercada options.timer-interval segundosrequiere timer-interval > 0

Las 16 mecánicas

MecánicaParámetrosEjemplo rápido

projectileprojectile (ARROW, FIREBALL, SNOWBALL, TRIDENT…), speed, damage, spread, count, yield{ mechanic: projectile, projectile: FIREBALL, yield: 2 }
potioneffect, seconds, amplifier, particles, target{ mechanic: potion, effect: SLOWNESS, seconds: 3 }

teleportmode: to-target / behind-target / random, distance{ mechanic: teleport, mode: behind-target }

Los placeholders de command y message son <mob>, <player>, <target>, <world>, <x> <y> <z>, <level>.

Inline vs archivo

Puedes escribir habilidades directamente en el mob (útil para jefes únicos) o reutilizar archivos:

# inline (dentro del mob) — como golem_obsidiana.yml
skills:
  onAttack:
    - { mechanic: velocity, mode: push, strength: 1.4, chance: 0.5 }
  onDeath:
    - { mechanic: explosion, power: 3, break: false }

# por id (reutilizable) — como duende.yml
skills: [duende_grito, duende_veneno]

Spawners

Cada archivo de spawners/ mantiene vivo un mob en una zona: mientras haya jugadores cerca y no se supere el máximo.

# spawners/bosque.yml
config-version: 2
mob: duende
world: world
x: 8
y: 64
z: 8
radius: 24         # area donde aparecen
interval: 45       # segundos entre intentos
max-alive: 3       # maximo de ese mob vivo en el radio
players-near: 64   # requiere jugadores a menos de 64 bloques (0 = siempre)
enabled: true
Gestión en juego
  • /nm spawner create <id> <mob> — crea un spawner donde estás parado
  • /nm spawner list — muestra vivos/máximo de cada uno (ej. prueba → duende @ world (2/3))
  • /nm spawner tp <id> — teletransporte
  • /nm spawner remove <id> — lo elimina
  • /nm edit spawners <id> interval 5 — cambia un campo y recarga al instante
Con boosts: los spawners consultan los multiplicadores activos — si hay una Luna Sangrienta, los duendes del spawner nacerán con ×1.5 vida y ×1.25 daño, y les tocarán sub-boosts.

Recompensas (rewards.yml)

Al matar un mob mítico, el asesino recibe puntos (para rangos), XP, items, comandos y un mensaje multicanal.

config-version: 2
default: { points: 1, xp: 5 }     # si un mob no tiene seccion propia

duende:
  points: 5
  xp: 8
  commands:
    - { cmd: "say  derrotó un Duende (+ pts)", chance: 0.2 }
  items:
    - { material: EMERALD, amount: 1, chance: 0.5, name: "&aEsmeralda duende" }
  message:
    actionbar: "&a+ puntos"
    sound: ENTITY_EXPERIENCE_ORB_PICKUP

guardian_hielo:
  points: 12
  message:
    title: "&b¡Guardián derrotado!"
    subtitle: "&7+ puntos y  XP"

Placeholders: <player>, <mob>, <mob-id>, <points>, <xp>, <world>. Si el inventario está lleno, el item cae al suelo.

Rangos y puntos

Los puntos acumulan por jugador (SQLite) y al cruzar un umbral sube de rango con recompensas y anuncio multicanal.

# ranks.yml (orden por puntos)
config-version: 2
ranks:
  - { id: novato,  display-name: "&7Novato",  points: 0 }
  - { id: cazador, display-name: "&aCazador", points: 25,
      rewards: ["give %player% iron_ingot 4"],
      announce: { chat: "&a%player% ahora es &2Cazador&a!", sound: ENTITY_PLAYER_LEVELUP } }
  - { id: asesino, display-name: "&cAsesino", points: 100,
      announce: { title: "&4&lASCENSO", subtitle: "%player% es ahora Asesino",
                  bossbar: { text: "&cAsesino: %player%", seconds: 5, color: RED } } }
  - { id: leyenda, display-name: "&6Leyenda", points: 300 }
  - { id: mito,    display-name: "&d&lMito",  points: 750 }
Comandos de progresión
  • /nm stats [jugador] — kills, puntos, rango y cuánto falta para el siguiente
  • /nm ranks — lista de rangos
  • /nm points add <jugador> <n> — para eventos o compensaciones

Cinco canales + chat

Todos los mensajes (boosts, rangos, mecánica message) usan el mismo formato multicanal. Si un canal no está, simplemente no se envía; si ninguno está, se degrada a chat.

announce:
  title: "&4&l¡LUNA SANGRIENTA!"        # titulo grande
  subtitle: "&7Duración: "     # subtitulo
  actionbar: "&cLos mobs se enfurecen"   # barra de accion
  bossbar:                               # barra de jefe (se oculta sola)
    text: "&c&lLuna Sangrienta &7— "
    progress: 1.0        # 0.0 a 1.0
    seconds: 8           # cuanto tiempo visible
    color: RED           # RED, BLUE, GREEN, YELLOW, PURPLE, WHITE, PINK
  sound:
    name: ENTITY_WITHER_SPAWN
    volume: 1
    pitch: 0.6
  chat: "&cEl evento ha comenzado."     # y siempre, chat
Para consola: cuando no hay jugadores conectados (o el destino es la consola), NMythic degrada automáticamente el mensaje a chat para que no se pierda nada en el log.

Colores y MiniMessage

Tres formatos, mezclables en la misma cadena:

"&aVerde legacy y <#ff2020>hex corto"
"<gradient:#ff2020:#7a0000>&lLuna Sangrienta</gradient>"   # MiniMessage
"<click:open_url:'https://cheftgamer.github.io/NMythic/'>&b&l▶ Wiki de NMythic</click>"
"<hover:show_text:'Clic para abrir'>&dEnlace</hover>"
  • Legacy: &a, &l… (y §)
  • HEX: &#RRGGBB o <#RRGGBB>
  • MiniMessage: <gradient>, <bold>, <rainbow>, <click>, <hover>… (Paper incluye MiniMessage de serie)

/nm edit

Edición rápida por chat sin abrir archivos. Cada cambio se guarda y recarga con validación al instante (~15ms):

/nm edit mobs duende                    # ver todo el contenido
/nm edit mobs duende health 40          # cambiar un campo
/nm edit mobs duende display-name "&aDuende Jefe &7[lv.]"
/nm edit mobs duende equipment.main-hand DIAMOND_SWORD
/nm edit spawners bosque interval 30
/nm edit boosts luna_sangrienta duration 600
/nm edit <tipo> <id> <campo> clear      # borrar un campo

Los campos disponibles por tipo se listan con /nm edit <tipo> <id> sin valor, y hay autocompletado con TAB.

Editor web

NMythic incluye un servidor web propio (sin nginx ni bases externas): editor de YAML con validación en vivo, listado de backups, recarga del plugin y asistente IA.

/nm web→ copiar enlace con token→ abrir en el navegador→ editar · validar · guardar→ ⟳ Recargar plugin 
[NMythic] ■ Editor web — activo
          URL: http://127.0.0.1:8765
          Token: 669e972905b8c61570662911cedbeff0
          Acceso 1 clic: http://127.0.0.1:8765/?token=669e...
          Puerto: 8765 (bind 127.0.0.1) fallback auto
  • Token de acceso: se genera solo en data/web-token.txt. Rota con /nm web token.
  • Autenticación: cabecera Authorization: Bearer <token>, ?token= o el login de la propia página.
  • API REST: /api/status, /api/files?type=mobs, /api/file (GET/PUT/DELETE), /api/validate, /api/reload, /api/backups, /api/wiki, /api/ai.
  • El PUT valida antes de guardar: un YAML roto devuelve HTTP 422 con la tabla de errores (línea, columna y solución) — el archivo NO se toca.

Puertos de hosting, al estilo Plan NUEVO

En hostings con panel (Pterodactyl, etc.) solo puedes usar los puertos que te asignan. NMythic lo resuelve igual que Plan, con cuatro ajustes en settings.yml > web:

web:
  enabled: true
  port: 8765                 # puerto fijo por defecto
  port-from-env: ""          # NOMBRE de variable de entorno con el puerto otorgado
  port-auto-fallback: true   # si el puerto esta ocupado prueba port+1..port+25
  bind-address: "127.0.0.1"  # 127.0.0.1 solo local | 0.0.0.0 accesible desde fuera
  public-address: "auto"     # auto | dominio o URL completa para los enlaces
EscenarioConfiguración
Servidor local / VPSport: 8765 y bind-address: "127.0.0.1" (por defecto)
Pterodactyl con asignación de puertoPide una asignación extra, ponla en port, cambia bind-address: "0.0.0.0" y public-address a tu IP:puerto
Panel que inyecta el puerto por variableport-from-env: NMYTHIC_PORT — NMythic lee System.getenv() y usa ESE puerto exacto (sin fallback), avisando en el log
Proxy inverso (nginx/Cloudflare)bind-address: "127.0.0.1" + public-address: "https://editor.midominio.com"
# log al arrancar con variable de entorno:
[NMythic] ✔ Editor web: http://0.0.0.0:8902 (token: /nm web)
[NMythic] Hosting: puerto tomado de la variable NMYTHIC_PORT = 8902
[NMythic] Bind 0.0.0.0: accesible desde fuera — usa el puerto
          otorgado por tu hosting y ajusta web.public-address
En caliente (sin reiniciar el servidor)
  • /nm web port 8890 — cambia el puerto y reinicia el editor
  • /nm web bind 0.0.0.0 — cambia la interfaz de escucha
  • /nm web public http://panel.ejemplo.com:8890 — la URL que muestran los enlaces
  • /nm web fallback off — desactiva el salto automático de puerto
  • /nm web env NMYTHIC_PORT — fija la variable a consultar
  • /nm web restart · /nm web token (rota el token) · /nm web off/on

Asistente IA

El panel derecho del editor web genera YAML describiendo lo que quieres. Compatible con cualquier endpoint estilo OpenAI: OpenAI, OpenRouter, un ollama local…

web:
  ai:
    url: "http://localhost:11434/v1/chat/completions"   # ollama local
    api-key: ""            # vacio para ollama
    model: "llama3"        # o gpt-4o-mini, etc.

Escribe «un jefe de fuego con 200 de vida y habilidades de explosión», pulsa Generar YAML y la respuesta cae en el editor lista para validar. El plugin inyecta un system-prompt con la estructura exacta de NMythic para que la IA no invente claves.

Backup automático (48h + pin)

Antes de cada recarga o guardado (comando, edit o web) NMythic copia mobs/, boosts/, skills/, spawners/, rewards.yml, ranks.yml y settings.yml a backups/<fecha>/.

backup previo→ migrar config-version→ validar + cargar→ si hay errores: restaurar y CANCELAR
  • Limpieza: cada 6h se borran los backups de más de 48h (configurable en backup.retention-hours)…
  • …salvo pineados: /nm backup pin <id> los conserva para siempre (◆ en la lista).
  • Restaurar: /nm backup restore <id> y luego /nm reload.
/nm backup list
◇ 20261115-180534-559  hace 39s  (reload:web)
◆ 20261115-180449-988  hace 1m   (reload:arranque)   ← pineado
/nm backup pin 20261115-180449
/nm backup clean   # borra los caducados no pineados

Migración config-version

Cuando una futura versión cambie el formato, cada archivo lleva config-version y NMythic migra solo, con dos estrategias:

SIN ediciones tuyas

El archivo coincide con la plantilla del plugin → se regenera completo con la plantilla nueva (comentarios incluidos).

CON ediciones tuyas

Se conservan tus valores, se renombran las claves conocidas (p.ej. hp → health) y las que ya no existen se mueven intactas a preserved-legacy:.

# antes (v1)                # después (v2), migrado por NMythic
version: 1                   config-version: 2
type: ZOMBIE                 type: ZOMBIE
display: "&bDuende..."       display-name: "&bDuende..."
hp: 55                       health: 55
atk: 9                       damage: 9
mi-clave-vieja: true         preserved-legacy:
                               mi-clave-vieja: true

El log te cuenta exactamente qué pasó: Migración: ancestro.yml v1 → v2 (renombradas: display → display-name, hp → health, atk → damage) (a preserved-legacy: mi-clave-vieja). También puedes forzarlo con /nm migrate.

Items externos (IA: / NEXO: / ORAXEN:)

En cualquier campo material (equipo o drops) puedes usar items de otros plugins; NMythic los resuelve por reflexión sin compilar contra ellos:

equipment:
  main-hand: { material: "IA:custom_sword_ruby" }
drops:
  - { material: "NEXO:enchanted_fruit", chance: 0.3 }
  - { material: "ORAXEN:mythic_charm", chance: 0.1 }
Si el plugin no está o el id no existe, se registra un aviso y el item se ignora — nunca crashea.

Compatibilidad 1.20 – 1.21

  • Compilado contra Paper 1.20.4 (API 1.20, bytecode Java 17) — funciona en 1.21.x sin cambios.
  • Los enums renombrados se resuelven en ambos sentidos: partículas (REDSTONE ↔ DUST, SPELL ↔ EFFECT, VILLAGER_ANGRY ↔ ANGRY_VILLAGER…), efectos (SLOW ↔ SLOWNESS, JUMP ↔ JUMP_BOOST…) y atributos (GENERIC_MAX_HEALTH ↔ MAX_HEALTH).
  • Puedes escribir las configs con nombres de 1.20 o de 1.21: NMythic traduce según el servidor donde corran.
